# dev-tools

*Note de synthèse vivante — mise à jour automatiquement à chaque nouvel apport.*

## Synthèse

Cette note couvre des outils facilitant différentes étapes du cycle de vie d'un projet dev, du déploiement à la communication, en passant par la génération d'applications, le traitement de documents, la capture vidéo et l'optimisation des workflows IA.

**Déploiement** : Vercel Drop permet de déployer un fichier ou dossier en le glissant directement dans le navigateur, sans Git, CLI ni configuration locale préalable. L'outil détecte automatiquement le framework utilisé — Next.js, mais aussi les exports d'outils comme Bolt.new, Claude Design ou Google Stitch — et lance le build correspondant ; les sites statiques sans framework sont déployés tels quels, sans étape de build. Si aucun `index.html` n'est présent à la racine, l'utilisateur choisit lui-même la page racine du site. Chaque drop crée un nouveau projet avec une URL de production live en quelques secondes ; un dépôt Git peut ensuite y être connecté pour passer à des déploiements automatiques.

**Génération d'applications par IA** : Higgsfield Apps, présentée comme la plus grosse release de Higgsfield à ce jour, permet de générer des applications complètes intégrant nativement les modèles d'image et vidéo de la plateforme. Le moteur Fable 5 conçoit le code applicatif au niveau d'un ingénieur senior, couvrant un large spectre : sites web complexes, extensions navigateur, plugins, applications desktop et mobile, avec déploiement direct une fois l'app générée. La solution est accessible via Supercomputer et, surtout, directement depuis Claude grâce au MCP (Model Context Protocol) de Higgsfield — une intégration qui rejoint la tendance d'orchestration d'outils IA complémentaires autour de Claude Code déjà observée avec NotebookLM et anydoc (voir plus bas).

**Communication / marketing produit** : le skill Claude Code `/brag` génère automatiquement une vidéo de lancement (~20 secondes, musique, animations, effets sonores) à partir d'un simple prompt ("/brag about this"), pour n'importe quel side project. Il s'appuie sur HyperFrames, le moteur open-source HTML-to-video de HeyGen, propose plusieurs presets de style et génère aussi le copy prêt à partager. L'outil vise à remplacer les posts de lancement peu engageants (simples screenshots statiques) par un format vidéo professionnel. Gratuit, open source, avec des démos incluses pour tester sans projet réel.

**Capture d'écran et vidéo** : CleanShot 5.0 introduit un Studio Mode permettant de transformer un enregistrement d'écran basique en vidéo soignée et professionnelle. L'interface permet de personnaliser finement le curseur — taille (jusqu'à 3x), style, visibilité — ainsi que son type de mouvement (Natural ou Smooth), pour ajuster le rendu visuel final. Contrairement au skill `/brag` qui génère automatiquement une vidéo de lancement à partir de code, CleanShot 5.0 se positionne sur l'édition manuelle et le rendu de captures d'écran existantes (démos, tutoriels). La fonctionnalité est disponible immédiatement sur tous les plans, sans surcoût ni abonnement additionnel.

**Traitement de documents pour agents IA** : Firecrawl a open-sourcé anydoc, un convertisseur universel de documents (docx, pptx, xlsx, PDF, epub, rtf... — 14 formats) vers Markdown (GFM), écrit en Rust pur, 100% local et sans modèle ML. Ses performances sont remarquables (médiane ~5ms par fichier vs ~1100ms pour LibreOffice, soit 500 docx convertis en 1,7s), ce qui permet une intégration *synchrone* dans une boucle d'agent IA sans file d'attente asynchrone complexe — un choix d'architecture qui tranche avec les outils reposant sur des modèles ML plus lourds. La détection de format s'appuie sur l'analyse du contenu plutôt que sur l'extension, ce qui permet de rejeter proprement les faux fichiers et de repérer des documents corrompus dans un dossier. L'outil reste honnête sur ses limites : un PDF scanné renvoie "Unsupported" plutôt qu'un résultat approximatif, l'OCR restant à la charge de l'utilisateur. La gestion d'erreurs est catégorisée (encrypted, unsupported, malformed) dès la version 0.1.x, avec un taux de succès de 98% sur fichiers valides. Intégration en une commande pour les agents IA : `npx skills add firecrawl/anydoc`.

**Optimisation des workflows IA / gestion du contexte** : une astuce propose de connecter Claude Code à NotebookLM pour utiliser ce dernier comme couche de mémoire/contexte externe, plutôt que de tout faire transiter par le contexte du LLM. L'objectif serait d'économiser des tokens et de prolonger la durée effective des sessions de codage assisté par IA. Cette approche s'inscrit dans une tendance plus large d'orchestration d'outils IA complémentaires pour contourner les limites de contexte et de capacités natives des LLM — tendance que confirment à la fois l'intégration de Higgsfield Apps à Claude via MCP (protocole standardisé) et l'intégration d'anydoc via un skill dédié, qui délègue à un outil local ultra-rapide une tâche (conversion de documents) que le LLM devrait sinon gérer plus lentement ou moins fiablement dans son propre contexte.

Une autre source annonce, séparément, une méthode permettant de réduire de 90% l'usage de tokens sur Claude Code, présentée comme simple mais négligée par la majorité des utilisateurs. Aucun détail technique n'est cependant exploitable : le contenu concret n'existe que dans une vidéo jointe non transcrite, l'image capturée ne montrant qu'une personne parlant devant un micro. Il n'est donc pas possible de vérifier si cette méthode recoupe l'approche NotebookLM (mémoire externe) ou relève d'une technique distincte (ex. gestion du prompt, compaction de contexte, sous-agents).

Sur un registre voisin mais appliqué à Codex plutôt qu'à Claude Code, un prompt réutilisable propose de faire auto-optimiser sa configuration par le modèle lui-même : Codex analyse l'historique des sessions passées et les habitudes de travail de l'utilisateur, croise ces observations avec la documentation de référence des clés de `config.toml` (agents, approval_policy granulaire, hooks lifecycle, features, network proxy, permissions...), puis suggère des réglages personnalisés parmi les nombreux leviers fins généralement ignorés par défaut. La méthode recommande de demander systématiquement le bénéfice concret de chaque changement avant de l'appliquer, pour éviter d'adopter des options inutiles ou risquées. Ce pattern — analyser l'usage réel + documentation structurée de config + proposer des améliorations contextualisées — est présenté comme généralisable à d'autres outils dev configurables, et rejoint la tendance de fond de cette note : déléguer à l'IA elle-même (ou à des outils tiers orchestrés) l'optimisation de son propre environnement de travail, plutôt que de s'appuyer sur des réglages génériques.

⚠️ Manque de matière : à ce stade, deux sources évoquent des gains d'efficacité tokens/contexte pour Claude Code (NotebookLM en couche de mémoire externe, et l'astuce à 90%) sans qu'aucune ne documente précisément son mécanisme technique — la source NotebookLM reste très synthétique sur le protocole/API utilisé, et la source "90%" ne fournit aucun contenu exploitable au-delà de l'annonce elle-même. Le prompt d'auto-configuration Codex est mieux documenté sur son principe (méta-prompt + doc de référence config.toml) mais reste lui aussi sans exemple concret de suggestions générées ou de gains mesurés. Par contraste, Higgsfield Apps (MCP explicite) et anydoc (mécanisme et architecture bien documentés) restent les cas les mieux sourcés de cette note.
